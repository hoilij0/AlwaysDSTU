# Always DSTU

Настольный прототип для лабораторной работы № 6. Пользователь выбирает группу, получает расписание с сайта ДГТУ, сохраняет снимок в PostgreSQL и просматривает офлайн карточки занятий за выбранный день. К занятию можно добавить, изменить или удалить заметку. Приложение считает пары и суммарное учебное время за день, неделю или месяц, а после изменения расписания показывает добавленные, отменённые и изменённые занятия. При ошибке или пустом ответе API прежний снимок не заменяется.

## Требования

- Python 3.12 или новее;
- PostgreSQL;
- Tkinter (входит в стандартную поставку Python для Windows);
- Зависимости `psycopg` и, на Windows, `truststore` из `requirements.txt`.

На Windows приложение автоматически ищет `libpq.dll` в стандартной папке установки PostgreSQL. Если PostgreSQL установлен в нестандартное место, укажите путь к папке с `libpq.dll` в `PG_LIBDIR`.

## Первичная настройка PostgreSQL

Перейдите в папку `AlwaysDSTU`, создайте виртуальное окружение и установите драйвер:

```powershell
python -m venv .venv
if (Test-Path .\.venv\Scripts\Activate.ps1) { .\.venv\Scripts\Activate.ps1 } else { .\.venv\bin\Activate.ps1 }
python -m pip install -r requirements.txt
```

Если `pip` не установлен в выбранной версии Python, сначала выполните `python -m ensurepip --upgrade`, затем повторите создание окружения и установку.

По умолчанию приложение использует `127.0.0.1:5432`, базу `always_dstu` и пользователя `postgres`. Если параметры локального PostgreSQL отличаются, задайте их в PowerShell перед запуском. Пароль, если он требуется, задаётся только в переменной окружения `PGPASSWORD` и не хранится в репозитории.

```powershell
$env:PGHOST = "127.0.0.1"
$env:PGPORT = "5432"
$env:PGDATABASE = "always_dstu"
$env:PGUSER = "postgres"
$env:PGPASSWORD = "<пароль PostgreSQL>"
```

Создайте базу при её отсутствии и примените схему из `Always DSTU.sql`:

```powershell
python setup_database.py
```

Скрипт не удаляет существующие таблицы или данные. Он создаёт базу `PGDATABASE`, если она отсутствует, и применяет идемпотентную схему проекта.

## Запуск

На этом ноутбуке можно дважды щёлкнуть **`Always DSTU.exe`** в папке `AlwaysDSTU`. Это небольшой Windows-запускатель: он открывает актуальный `main.py` из той же папки через локальное окружение `.venv`, поэтому программа использует последние изменения кода. Не переносите один `.exe` отдельно: для работы нужны файлы проекта, настроенное окружение Python и работающая PostgreSQL. Это не автономный установщик и не готовый пакет для других компьютеров.

Запускатель создаётся локально и не добавляется в Git. Исходный код — `launcher.cs`; иконка для EXE и окон находится в `AlwaysDSTU/assets/icon.ico`, её исходное изображение — `icon.png`. При наличии стандартного компилятора .NET Framework запускатель с иконкой можно пересобрать из корня проекта:

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' /nologo /target:winexe /codepage:65001 /reference:System.Windows.Forms.dll '/win32icon:AlwaysDSTU\assets\icon.ico' '/out:AlwaysDSTU\Always DSTU.exe' 'AlwaysDSTU\launcher.cs'
```

Альтернативно приложение можно запустить из командной строки после активации окружения:

```powershell
python main.py
```

При первом запуске можно указать локальный ник и выбрать группу; настройку можно отложить и открыть позже через «Профиль и настройки». Там же находится переключатель светлой и тёмной темы. При следующих запусках приложение открывает последнюю выбранную группу и сначала показывает локальный кэш, затем в фоне проверяет обновление. Если начался новый месяц, а для него ещё нет сохранённых занятий, открывается предыдущий сохранённый месяц — его можно просматривать без интернета. На главном экране выберите день в полоске недели; стрелки переключают недели, включая соседние месяцы. Под датой указано число сохранённых пар: одна — зелёным, две — желтовато-зелёным, три — жёлтым, четыре и больше — красным. Нейтральный ноль означает отсутствие пар в сохранённых данных, прочерк — отсутствие данных о дне. Для граничной недели используются сохранённые данные соседнего месяца в пределах ответа сайта; их полнота зависит от источника. Если выбранный месяц ещё не сохранён, приложение пробует его загрузить. При ошибке сети предыдущий кэш не удаляется: к нему можно вернуться, выбрав день сохранённого месяца. Отметка последней успешной синхронизации относится к показанному сохранённому месяцу; для месяца без кэша она не показывается. Кнопка «Обновить» расположена рядом с заголовком расписания. Нажатие на карточку занятия открывает заметку. При закрытии формы с несохранённым текстом приложение просит подтвердить его отмену. «Аналитика и изменения» показывает сводку периода и сравнивает два последних снимка; очистка кэша группы находится в профиле и удаляет её снимки, занятия и заметки после подтверждения.

После синхронизации строка состояния сообщает, были ли обнаружены изменения, и показывает число добавленных, отменённых и изменённых занятий. Подробности доступны в аналитике. Это уведомление внутри открытого приложения; системных push-уведомлений нет.

Карточка занятия открывается нажатием в любом её месте; при управлении с клавиатуры выберите карточку клавишей Tab и нажмите Enter или пробел. Полный текст заметки виден в открывшейся форме. Дата для аналитики соответствует дню, показанному на карточках.

Группа выбирается только в разделе «Профиль и настройки». Кнопка «Найти» открывает поиск по части названия без учёта регистра; там же расположена кнопка «Загрузить группы» для получения полного справочника с сайта. Без интернета доступны локальные группы. Найденный вариант применяется после сохранения профиля; загрузка справочника сама по себе текущую группу не меняет. Полный справочник отдельно для офлайн-поиска пока не сохраняется.

При синхронизации дополнительно сохраняются занятия соседних месяцев, необходимые для полных граничных недель выбранного месяца. Сводка использует их и без интернета. Если кэш был создан старой версией приложения, нужно один раз синхронизировать расписание, чтобы сохранить эти дни. Если ответ сайта не охватывает неделю, приложение предупреждает о возможной неполноте. По кнопке «Проверить неделю на сайте» можно выполнить временный расчёт по актуальному ответу API, не изменяя кэш. Полнота данных зависит от опубликованного сайтом периода.

Сравнение снимков сопоставляет занятия по дате, дисциплине и другим данным. Поскольку в текущей модели нет постоянного идентификатора занятия от источника, при сложных заменах сравнение может показать отмену и добавление вместо одного изменения; результат стоит сверить с расписанием.

## Ручная проверка перед демонстрацией ЛР6

Проверку можно выполнить на своём ноутбуке после настройки базы. Используйте пару, у которой **нет существующей заметки**, и тестовый текст: это позволит не изменять чужие записи. PostgreSQL должен работать и в онлайн-, и в офлайн-режиме.

1. При подключённом интернете запустите приложение, выберите группу и нажмите «Синхронизировать расписание». Дождитесь появления занятий и времени последней синхронизации.
2. Укажите ник в «Профиль и настройки», если ещё не сделали этого. В полоске недели выберите день, а затем карточку пары без заметки. Попробуйте сохранить пустой текст: приложение должно показать предупреждение и оставить форму открытой. Введите, например, «Тест ЛР6: подготовить материалы». Для отчёта сделайте снимок заполненной формы до сохранения.
3. Нажмите «Сохранить»: на карточке должна появиться отметка «Есть заметка». Сделайте снимок главного окна и повторно откройте пару, чтобы проверить полный текст. Закройте и заново откройте приложение — заметка должна сохраниться.
4. После первоначальной загрузки временно отключите интернет, перезапустите приложение и проверьте, что сохранённые занятия и тестовая заметка видны. Верните интернет после проверки. Если месяц сменился, приложение откроет последний сохранённый месяц.
5. Откройте свою тестовую заметку, измените текст и сохраните; проверьте её повторным открытием. Затем удалите **только созданную тестовую заметку** и подтвердите удаление. Отмена подтверждения должна сохранять заметку.
6. Выберите дату с занятиями и откройте «Аналитика и изменения». Для дня сравните число пар и суммарное время с расписанием. Список изменений можно проверить, только когда есть два разных снимка одного месяца; если их нет, не обозначайте этот ручной сценарий как пройденный. Классификация добавлений, отмен и изменений также проверяется автоматическими тестами.

Кнопка «Очистить кэш группы» удаляет её сохранённые снимки и заметки, включая заметки других месяцев. Для проверки этой кнопки используйте отдельную тестовую базу или предварительно согласуйте удаление всех этих данных. Фактические результаты и скриншот актуальной Канбан-доски добавляются в отчёт после выполнения проверки.

## Источник расписания

Клиент повторяет способ получения данных из примера IKMS: запрашивает список групп через `raspGrouplist`, а расписание группы — через `Rasp?idGroup=...` на `https://edu.donstu.ru/api/`. В HTML сайта приложение не парсит. На Windows сертификат сервера проверяется с помощью системного хранилища доверенных сертификатов. Существующий снимок расписания остаётся в PostgreSQL при недоступности API, пустом или некорректном ответе. Если расписание совпадает с сохранённой версией, приложение записывает успешную синхронизацию в журнал, но не создаёт дублирующий снимок.

Чтобы снизить риск потери расписания из-за неполного ответа, при обновлении того же месяца приложение проверяет резкое уменьшение количества занятий. Если в кэше было не менее шести занятий и сайт вернул меньше половины, при автоматической проверке кэш сохраняется и показывается предупреждение. При ручной синхронизации можно проверить данные на сайте и явно подтвердить замену. Это эвристика, а не гарантия обнаружения неполного ответа: реальные изменения тоже могут её вызвать, а неполный ответ с большим числом записей — не вызвать.

API может вернуть занятия сразу за несколько месяцев, но приложение сохраняет выбранный месяц и только те дни соседних месяцев, которые входят в его первую и последнюю недели. При успешной загрузке другого месяца прежний месячный кэш расписания удаляется; при ошибке сети прежний кэш сохраняется. Для сравнения изменений остаются два последних снимка выбранного месяца. Заметки при смене месяца или отмене пары сохраняются отдельно: их можно прочитать, изменить или удалить через «Другие сохранённые заметки», а при повторной загрузке подходящего занятия приложение восстанавливает связь. Если однозначно сопоставить занятия невозможно, заметка остаётся отдельно.

Заметки сейчас хранятся только в локальной PostgreSQL и не синхронизируются между устройствами. Ник без регистрации задаётся один раз в профиле и автоматически используется при сохранении заметки; его можно изменить в настройках. Изменение ника не переписывает старые заметки, но при последующем редактировании заметка подписывается текущим ником. Старые заметки без подписи сохраняются с пометкой «автор не указан». Ник не является учётной записью и не подтверждает личность. Если расписание обновилось в другом окне во время редактирования, приложение не запишет заметку в старую версию: оно предложит скопировать текст и открыть занятие заново. Очистка кэша группы по кнопке после подтверждения удаляет также сохранённые отдельно заметки.

## Проверка преобразования ответа API

Тесты используют фиксированные JSON-ответы, не требуют интернета или подключения к PostgreSQL:

```powershell
python -m unittest discover -s tests
```

Проверки покрывают разбор ответов API, расчёт числа пар и учебного времени, классификацию изменений расписания и контракт чтения истории/очистки кэша. Tkinter-интерфейс и реальное подключение к PostgreSQL нужно дополнительно проверить на компьютере каждого участника с установленным драйвером `psycopg`.

Для дополнительных интеграционных проверок на работающем PostgreSQL (создаются и удаляются отдельная тестовая группа и временная схема; пользователю БД нужны права на создание схемы):

```powershell
$env:ALWAYS_DSTU_TEST_DB = '1'
python -m unittest discover -s tests -p 'test_postgres_notes.py' -v
python -m unittest discover -s tests -p 'test_fresh_setup.py' -v
Remove-Item Env:ALWAYS_DSTU_TEST_DB
```

Для проверки пользовательских сценариев окна в активном графическом сеансе:

```powershell
$env:ALWAYS_DSTU_TEST_GUI = '1'
python -m unittest discover -s tests -p 'test_gui_scenarios.py' -v
Remove-Item Env:ALWAYS_DSTU_TEST_GUI
```

Эти проверки используют тестовые данные и не изменяют локальное расписание. Они проверяют сохранение и удаление заметки, пустой ввод, ошибку базы, отсутствие сети и выбор месяца.

Сквозной тест окна с настоящей PostgreSQL и имитацией ошибки сети требует оба параметра. Он создаёт отдельную временную схему и удаляет её после проверки:

```powershell
$env:ALWAYS_DSTU_TEST_DB = '1'
$env:ALWAYS_DSTU_TEST_GUI = '1'
python -m unittest discover -s tests -p 'test_full_scenario.py' -v
Remove-Item Env:ALWAYS_DSTU_TEST_DB
Remove-Item Env:ALWAYS_DSTU_TEST_GUI
```
